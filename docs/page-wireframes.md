# Page Wireframes

## 1. 设计目标

结果页必须同时做到两件事：

- 让用户在 30 秒内得到“可行动的结论”
- 让用户在 1 分钟内验证“这些结论是不是靠谱”

因此页面结构采用“结论在上，证据在下”的设计。

## 2. 首页 / 搜索页

### 页面目标

- 让用户快速发起一次搜索
- 让首次使用者理解产品价值
- 给出示例查询降低输入门槛

### 低保真线框

```text
+--------------------------------------------------------------+
| 面经雷达                                                     |
| 输入公司、岗位、方向，自动总结流程、周期和高频问题          |
|                                                              |
| [公司________] [岗位________] [方向________] [开始分析]      |
|                                                              |
| 热门示例：                                                   |
| [美团 / 产品实习 / 增长]  [腾讯 / 商业分析实习 / 策略]       |
| [字节 / 产品经理实习 / 商业化]                              |
|                                                              |
| 我们会返回：                                                 |
| - 典型面试流程                                               |
| - 面试周期                                                   |
| - 高频问题                                                   |
| - 来源证据                                                   |
+--------------------------------------------------------------+
```

### 组件建议

- Hero 区域
- 三段式搜索输入
- 热门示例 chips
- 产品可信机制说明

## 3. 结果页

### 页面目标

- 用一个页面讲清“结论是什么”
- 支持用户快速钻取来源

### 信息架构

1. 查询头部
2. 总览卡片
3. 面试流程时间线
4. 周期统计
5. 高频问题
6. 证据来源列表

### 低保真线框

```text
+----------------------------------------------------------------------------------+
| 查询：字节跳动 / 产品经理实习 / 增长                                [重新搜索]    |
| 样本 18 篇  最近更新时间：2026-04-25  置信度：中高                              |
+----------------------------------------------------------------------------------+
| 总览                                                                            |
| 常见流程：HR -> 业务一面 -> 业务二面/leader 面 -> HR                           |
| 中位周期：12 天                                                                  |
| 高频主题：增长分析 / 用户洞察 / 项目复盘 / SQL 基础                             |
+--------------------------------------+-------------------------------------------+
| 面试流程时间线                         | 周期统计                                  |
| 1. HR 初筛：机动性、过往经历           | 投递到 HR：1-3 天                         |
| 2. 业务一面：项目经历、增长案例        | 一面到二面：2-5 天                        |
| 3. 二面/leader：业务判断、优先级排序   | 终面到结果：3-7 天                        |
+--------------------------------------+-------------------------------------------+
| 高频问题 Top 10                                                               |
| 1. 你做过的增长项目里，最核心的指标是什么？  [7 次] [看证据]                    |
| 2. 如果新用户转化下降，你会怎么定位问题？      [6 次] [看证据]                    |
| 3. 讲一个你和研发/运营协作推进项目的例子。     [5 次] [看证据]                    |
+----------------------------------------------------------------------------------+
| 来源证据                                                                        |
| - 来源 A：2025-10，某社区帖子，相关度高         [展开原文片段] [打开链接]         |
| - 来源 B：2025-08，博客文章，相关度中           [展开原文片段] [打开链接]         |
| - 来源 C：2024-11，经验分享页，相关度高         [展开原文片段] [打开链接]         |
+----------------------------------------------------------------------------------+
```

### 交互建议

- 点“看证据”后打开右侧抽屉
- 不离开当前页即可看原文片段
- 同时展示这条问题来自哪些轮次

## 5. 来源管理页（可选）

如果你还有时间，可以加一个内部页，方便面试时展示“系统不是黑箱”。

### 可展示内容

- 抓取到的原始 URL
- 抽取是否成功
- 报告相关度
- 去重状态
- 失败原因

这页不一定给真实用户看，但很适合面试现场展示你的工程思路。

## 6. 视觉建议

如果你真要做成 demo，不建议走“朴素后台风”。更适合这个项目的风格是：

- 搜索页像一个轻量研究工具
- 结果页像一个情报仪表盘
- 重点强调时间线、统计卡片、引用抽屉

## 7. 页面文案建议

### 首页主标题

在投递前，看清这场面试大概率会发生什么

### 首页副标题

自动搜索公开面经，提炼流程、周期和高频问题，并展示证据来源

### 结果页提示文案

- 结论基于公开样本自动聚合，存在样本偏差
- 点击任意问题可查看引用证据
- 优先参考最近一年的样本
